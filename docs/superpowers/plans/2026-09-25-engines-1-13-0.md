# Engines 1.13.0: manual v4 y arranque en formato 2 de Engram 1.7.0

> Como cambiar el reglamento pegado en el escritorio de cada empleado y la hoja de resumen de cada mañana por las versiones nuevas que ya entrega el archivero, sin dejar sin papeles a una oficina que todavía tenga un archivero viejo.

**Qué es:** el plan para que `forge614-engines` (hoy v1.12.1, `a6bfc2b`) use lo que ya publica Engram 1.7.0: el manual de memoria del protocolo v4 y el bloque de arranque en formato 2. Es el paso 2 del orden de la spec de memoria inteligente (§9: «Engines acepta y renderiza v4 completo; el gancho inyecta el bloque de Engram»).
**Decisiones del propietario (2026-09-25):**
- **D1.** El manual v4 se instala tal cual (`instructions`); `mcpInstructions` no se escribe en ningún archivo (lo entrega el servidor MCP de Engram).
- **D2.** Con un Engram anterior a 1.7.0, Engines se adapta: si la v4 o `--format 2` responden `INVALID_INPUT`, usa el manual v1 o el formato 1 como hoy y avisa que conviene actualizar Engram.
- **D3.** `verify memory-integration` avisa (nunca falla) cuando el manual instalado difiere del que entrega Engram hoy, con el comando para actualizarlo.
- **D4.** El gancho inyecta el `text` del formato 2 sin reconstruirlo, con el tope defensivo de 10 500 caracteres.
- **D5.** Simetría entre agentes: el manual va incrustado dentro del archivo principal de cada agente, entre sus marcadores, como ya hace Codex. Claude Code deja el archivo aparte `~/.claude/forge614-engram-memory-protocol.md`; la migración lo retira solo si empieza con la marca de Engines y, si no, avisa.

**Fuera de este plan:** retirar el manual de los archivos y dejarlo solo en el MCP. Se decide con el escenario «solo teléfono» del banco de comportamiento (Engram, tema `forge614-ai/engram/manual-solo-por-mcp`).
